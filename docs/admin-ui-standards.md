# 管理后台界面规范

后台标准蓝本位于 `/admin/ui-standard/list`，源码在
`apps/admin/src/pages/ui-standard`。新增列表、表单或详情页面时，先复制
蓝本的结构，再替换业务字段和数据请求。

## 页面骨架

所有业务页面使用 `@/components/AdminPage`：

- 外层使用与 `/admin/dashboard/analysis` 相同的 `GridContent`，页面内容
  左右边界必须与该页面一致，不再叠加 `PageContainer` 内边距；
- 页面顶部必须包含面包屑；
- 页面标题使用 `PageContainer` 的标准字号，不添加页面描述；
- 页面级操作放在标题栏右上角；
- 窄屏通过 Ant Design 响应式栅格自然降级，不写固定桌面宽度。

## 列表与筛选

- 行操作统一收进 `Dropdown`，触发按钮使用 `EllipsisOutlined` 三点图标。
- 不在每行平铺“查看 / 编辑 / 删除”等多个文字链接。
- 筛选栏独立放在列表上方，`Form` 必须使用 `layout="vertical"`。
- 筛选卡片不显示“筛选条件”等重复标题。
- 筛选条件默认完整展示，不提供展开/收起。
- 标签位于控件上方，长标签不得挤压输入控件。
- 查询与重置按钮在字段栅格下方右对齐，使用“重置、查询”顺序。
- 新增、快速新增、导入等主业务按钮放在列表工具栏左侧。
- 列表使用 `ProTable`；刷新、密度、列设置使用其原生图标工具并放在右侧。
- 表格操作列固定在右侧，宽度只容纳三点按钮。
- 三点按钮使用带边框的 `MoreOutlined` 按钮；菜单项都带语义图标，
  文案使用“详情、编辑、复制、停用、删除”等简洁名称。

## 新增与编辑

- 可见表单字段超过 6 个时，必须使用独立路由页面。
- 6 个及以下的轻量表单优先使用 `Modal`，保留用户当前列表上下文。
- 独立表单按“基本信息、负责人信息、发布设置”等主题拆分 `Card`。
- 表单标签统一放在控件上方，使用响应式 `Row` / `Col` 布局。
- 返回、保存等操作放在独立页标题栏右上角，不在表单底部重复放置。
- 表单校验规则仍以后端为最终依据，前端只提供即时体验。
- 富文本字段统一使用 `@/components` 导出的 `TiptapEditor`。静态蓝本的
  图片使用 Data URL 演示适配器，不代表业务存储方案；业务接入必须走
  统一附件架构并保存可长期访问的图片 URL 与附件标识。HTML 清洗与展示
  必须保留 `span` 的 `color`、`font-size` 样式及图片 `width`、`height`
  属性，确保字体样式和图片缩放结果可以往返保存。

## 详情

- 详情使用独立页面，优先利用大屏宽度。
- 基本字段使用响应式 `Descriptions`，大屏显示 3–4 列，窄屏降为 1 列。
- 指标、关联数据、操作记录按独立卡片分区。
- 详情页保留返回和编辑操作，编辑进入标准独立表单页。

## 国际化

- 页面只支持 `zh-CN` 和 `en-US`。
- 所有界面文案通过 `useIntl`、`FormattedMessage` 或 locale 文件输出。
- 禁止在新增业务页面中直接写只面向一种语言的按钮、标题、状态和提示。
- 枚举值在数据层保持稳定英文编码，展示层通过 locale 映射。

## 静态蓝本路由

- `/admin/ui-standard/list`：筛选、工具栏、表格、三点操作和轻量弹窗。
- `/admin/ui-standard/create`：超过 6 项的独立新增页，并演示完整 Tiptap
  富文本编辑器。
- `/admin/ui-standard/edit/1001`：独立编辑页。
- `/admin/ui-standard/detail/1001`：大屏优先详情页。

蓝本使用本地静态数组，不调用 API，也不会写数据库。
