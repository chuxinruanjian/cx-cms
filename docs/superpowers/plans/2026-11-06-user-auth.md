# User Authentication Implementation Plan

> Implement inline using test-driven development and verification-before-completion.

**Goal:** 独立前台用户认证：用户名密码、微信小程序、公众号网页授权；统一提交当前系统配置及用户认证改动。
**Architecture:** Lucid 用户、独立令牌、微信身份、一次性 OAuth state、登录限流表；微信服务仅信任服务端换码结果。用户上传复用现有 UploadActor 服务。
**Tech Stack:** AdonisJS / Lucid / Vine / native fetch / Japa。

## Confirmed requirements and decisions

- 用户表包含 username、password、mobile、nickname、avatar；手机号暂为可空账户字段，不接受未验证的前台直接绑定。
- 微信创建账户自动随机用户名，默认 123456 仅保存哈希；按用户确认，在微信登录后设置至少 8 位新密码才允许密码登录。
- 用户有一次有意义的改名机会，以数据库条件更新保证并发安全；重复提交当前用户名不消耗机会。
- 公众号从服务端用户信息接口读取头像昵称，小程序单独上传头像、更新昵称，不信任登录请求附带的 openid/unionid/profile。
- 微信身份按 provider/appId/openid 的 SHA-256 键唯一；UnionID 按配置的开放平台命名空间哈希匹配，未配置平台时限定于 appId。避免 MySQL 默认大小写不敏感造成身份混淆。
- 同一开放平台已知 UnionID 关联同一用户；已有两个不同账户产生冲突时返回 409，不自动迁移业务数据。
- 公众号通过固定回调 URI 生成授权 URL，state 绑定浏览器会话、10 分钟过期并原子单次消费；微信 code/secret/session_key/token 不进入返回和日志。
- 新增 user guard 与 userAuth middleware；管理员认证保持独立。密码更新保留当前令牌、撤销其他令牌。
- 用户头像上传复用统一上传控制器和存储服务；不初始化 H5 或小程序框架。
- 使用专用 WECHAT_* 服务端环境变量，更新 .env.example 和接口文档；真实微信联调需要实际应用配置。
